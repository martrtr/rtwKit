# Ai Provider

One optional RTW has two attested roles. In baseline its ordinary backend owns a
non-secret local catalog; the sibling settings component edits it. In a World,
the backend reads the explicitly published catalog with a separate local grant,
uses that World's saved choice, and owns its own HTTP/operation/secret resources.
The baseline role does not generate. Model discovery uses its own HTTP/key-read
approvals, independently of every World.

Settings provides Ollama and OpenAI-compatible templates. Each World chooses its
connection and approves its own exact local origin or credential path. Opening settings automatically checks the model list with the scope backend.
The diagnostic may read an explicitly approved credential; no generation occurs. Mutations after unknown acknowledgements
are reconciled through Refresh, never automatically retried.

See [the inference contract](../../docs/specs/p10-narrator-ai.md) and the companion
Core `docs/specs/extension-settings-and-ai-connections.md` for authority and export
semantics. The same exact package must run in both scopes. Old exact RTWs retain
their original contract; no implicit migration of existing Worlds.

Psychology processing may use the existing text inference protocol: begin-generate
admits the exact selected `rintawa.memory` backend as well as selected Narrator,
within a World. Status/cancel/release remain bound to the initiating principal.
Psychology owns disclosure consent, settings, prompt and interpretation; AI Provider
has no psychological state or analysis-specific request fields.
